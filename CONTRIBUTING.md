# Contributing to lockcode

Thanks for your interest in contributing to this project. We welcome contributions from developers, designers, writers, and anyone who wants to help improve the project.

## Ways to contribute

You can contribute by:

- reporting bugs or suggesting improvements;
- improving documentation;
- fixing issues and submitting pull requests;
- proposing new features;
- helping with testing and feedback;
- improving project onboarding and examples.

## Before you start

Please make sure you:

- read the project README;
- understand the current issue or feature request;
- check whether a similar issue already exists;
- keep discussions respectful and constructive.

## Pull request workflow

1. Fork the repository.
2. Create a new branch for your work.
3. Make your changes.
4. Keep commits focused and clear.
5. Add or update tests when needed.
6. Open a pull request with a clear title and description.
7. Wait for review and address feedback.

## Code quality expectations

- Follow the existing coding style and project conventions.
- Write readable, maintainable code.
- Keep changes scoped to the issue or feature.
- Avoid unrelated edits in the same pull request.
- Include documentation updates when behavior changes.

## Commit message guidelines

Use clear and descriptive commit messages, for example:

- fix: resolve model connection error
- docs: add contributing guide
- feat: add local model support
- test: add API validation coverage

## Reporting issues

When opening an issue, include:

- a clear description of the problem;
- steps to reproduce it;
- expected behavior;
- actual behavior;
- relevant logs, screenshots, or environment details.

## Community guidelines

We expect contributors to be respectful, collaborative, and constructive. Harassment, spam, or disruptive behavior will not be tolerated.

## First contribution

If you are new to the project, look for issues labeled:

- good first issue
- help wanted
- documentation

These are often ideal starting points for first-time contributors.

## Recognition

Contributors are appreciated and recognized through GitHub pull requests, issue contributions, and project acknowledgements.

Thank you for helping make the project better.
